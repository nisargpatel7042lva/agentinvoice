# End-to-end run (2026-11-06)

Setup: the merged tree (`phase_4_hardening_sidd` after merging `main` incl. the web scaffold and investor agent). A local anvil chain with a stand-in `MockInvoiceMarket` that follows the spec v2 interface (NOT Mann's contract: no access control or money), the real backend started with `bun run dev:backend`, and the real Sepolia ENS name `buyer.agentinvoicenf71.eth` with the real publisher wallet.

## Passed

- `bun run verify`: typecheck, lint, 158 tests (21 files), forge, all green. `apps/web` `next build` succeeds.
- Indexer over real JSON-RPC: createInvoice, acceptInvoice, fund, markPaid, markLate, markDefaulted each appeared in `GET /api/invoices/:id` within 1 to 6 seconds (target 10). The funded invoice carried the right holder; filters by status worked; `/health` showed indexer lag of 1 to 3 seconds and `degraded: false`.
- ENS publisher on live Sepolia: paying an invoice set `paid = 1` within about 8 seconds; a Late then Defaulted invoice set `late = 1` and `status = defaulted`; `limit` and `threshold` were never touched; `/health` recorded `lastPublishAt`. The record was reset to paid 0, late 0, active afterwards.
- HTTP behavior: 404 unknown id, 400 bad id or status, 503 for unconfigured audit and World, 413 for a body over 16 KiB, 429 with `Retry-After: 60` after 10 approval starts in a minute, `/health` and the invoice list not limited. Seed rows (6 DEMO) show alongside chain rows with "DEMO" in the description.
- Approval flow over real HTTP (placeholder World client): correct authorize URL (state = approval id, PKCE S256, `max_age=0`, `prompt=login`, orb acr), 409 for a closed invoice, 404 for an unknown one, a cancel rejects the approval and redirects to `/approval/<id>?result=rejected&code=user_cancelled`, a later callback cannot revive it (`state_reused`), a forged state is an error. The redirect path matches the web app's `/approval/[id]` route.
- Clean shutdown on SIGINT for both servers; the logs contained no key or secret values and no error-level lines.
- The shared API client calls only endpoints the backend serves, with matching parameters, except the one gap below.
