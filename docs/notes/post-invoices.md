# POST /api/invoices (spec v2 section 3)

- Request body (matches `CreateInvoiceBody` in `packages/shared/src/api.ts`): `buyerVault`, `faceAmount`, `price`, `dueDate` (unix seconds, in the future), `description` (1 to 500 characters), `evidenceHash` (0x + 64 hex). Amounts are decimal strings greater than 0 and within uint256; `price` cannot exceed `faceAmount`.
- Behavior: the backend creates the invoice on-chain with `InvoiceMarket.createInvoice` from ONE issuer wallet (`SUPPLIER_PRIVATE_KEY`, needs `INVOICE_MARKET_ADDRESS`), confirms the invoice at the returned id is the one it created, stores it (source `chain`) with the description, and returns it as a Pending `Invoice` (201). The indexer later keeps the status in sync and never overwrites the description.
- Errors: 400 invalid body or past due date; 409 `duplicate_evidence` (the evidence hash already belongs to an invoice, with its id) or `in_progress` (the same hash is being created right now); 502 `chain_error` (nothing stored, the same request can be retried); 503 `issuer_not_configured`; 429 over 10 requests per minute per client.
- DEMO-MODE LIMITATION: `createInvoice` sets `supplier = msg.sender`, so every invoice created through this endpoint has the issuer wallet as its supplier. A real supplier would sign `createInvoice` from their own wallet. Anyone who can reach the endpoint can make the issuer spend gas: keep `SUPPLIER_PRIVATE_KEY` unset on any public deployment you do not mean to open, and keep the rate limit. The endpoint has no sign-in because spec v2 defines none.
- Unverified: `createInvoice`'s signature and its return value follow the frozen spec; Mann's real contract is not deployed yet. Run against a stand-in contract on anvil (chain id 296) the full path worked: POST, on-chain state, duplicate refusal, past-due refusal, and indexer sync of accept and fund with the description kept.
